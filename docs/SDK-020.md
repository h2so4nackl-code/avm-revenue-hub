# SDK 0.2.0 compatibility

On 14 October 2026, this standalone application passed the full check gate with
SDK 0.2.0 / guest SDK 0.1.1. Application contract logic, ABI identifiers, and
state schemas are unchanged; the vendored SDK and reviewed local-only Cargo.lock
are updated. There are 74 application and 13 SDK tests (87 executed tests).

The seven contracts across the three projects build with official two-clean-build
comparison, canonical IDs, zero host imports, and native/WASM Clippy. Each actual
AVM journey uses its own fresh temporary stand, handles rejected transfers and
retries, empties the queue, and replays its own account/registry roots and fees.
The SDK initializes random public identities, so independent stand roots need
not match. Evidence is in `evidence/VALIDATION.json`, `runtime-v020.json`, the
compressed complete `avm-e2e.json.gz`, and each build-provenance file.

The new builder rejects RUSTC_WRAPPER. Builds now use the supplied compiler
without a remapping wrapper. Official per-location reproducibility is tested;
byte identity across arbitrary source directory locations is not claimed.

The installer pins the outer archive hash and uses the unchanged upstream
release verifier from the immutable SDK commit to check every inner file and
manifest/profile/provenance binding before activation. It preserves existing
historical installation directories. Its fresh-directory rehearsal reproduced
the exact released host binaries, profile and manifest.

## Fresh local state

Keep historical tools/profile/state together for historical replay. SDK 0.2.0
does not migrate old local state: create a fresh stand, fund its derived
addresses and redeploy. Do not edit state headers or mix compiled caches.
This is a local-development change, not permission to reset production.

Linux x86-64-v3 and glibc >=2.39 are required. Python >=3.11, Bash, curl,
Rust/Cargo 1.93.0 and its wasm32 target are used by these project scripts.
The upstream gh downloader is replaced only by a pinned curl download; its
package verification is retained unchanged. On an existing checkout, choose a
fresh runtime directory if the legacy installation is a real directory:

```bash
bash scripts/install_runtime.sh .runtime-sdk020
# For Revenue Hub/Vesting, also install Binaryen with scripts/install_binaryen.sh.
bash scripts/check.sh "$PWD/.runtime-sdk020/avm-sdk-linux-x86_64"
```

The public standalone migration is separate from upstream integration PR
[#10](https://github.com/gosh-sh/avm-sdk/pull/10); this result does not assert
that its branch was rebased, reviewed, merged or rewarded. Ordinary payment
callbacks are tested; deploy success callbacks and guest internal-event reads
remain outside these scenarios. No mainnet deployment or real-fund test is claimed.
